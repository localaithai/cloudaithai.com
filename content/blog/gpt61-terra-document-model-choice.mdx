## OpenAI เปิด Terra ในช่องทางใด

OpenAI ประกาศ [GPT-6.1 Terra ผ่าน API เมื่อ 26 ตุลาคม 2026](https://developers.openai.com/api/docs/changelog) สำหรับงานภาพ การใช้คอมพิวเตอร์ และการเขียน ส่วน [บันทึกโมเดล](https://help.openai.com/en/articles/9624314-model-release-notes) ระบุการทยอยเปิดใน Work และ Codex ไม่ใช่ Chat การเข้าถึงแต่ละช่องทางจึงควรตรวจแยกกัน

[เอกสารประเมินความปลอดภัย](https://deploymentsafety.openai.com/gpt-6-1-terra) เตือนว่าผลจากสภาพแวดล้อมวิจัยหรือ API อาจต่างจาก ChatGPT จริง ข่าวนี้ยังไม่ใช่ผลทดสอบเอกสารไทยหรือการยืนยันว่า Mimir รองรับโมเดลแล้ว

## เอกสารแบบใดควรอยู่ในชุดเปรียบเทียบ

ข้อเสนอสำหรับผู้ซื้อคือเลือกงานที่ต้องส่งต่อให้คนใช้จริง แยกคำตอบที่ดูอ่านง่ายออกจากข้อมูลที่ตรวจย้อนกลับได้ ก่อนทดลองให้เจ้าของงานกำหนดช่องข้อมูลที่ผิดไม่ได้และกรณีที่ต้องหยุดรอคน

| งานตัวอย่าง | หลักฐานที่เตรียมไว้ | เกณฑ์รับที่เสนอ |
| --- | --- | --- |
| อ่านใบเสนอราคาสแกน | รายการ รุ่น จำนวน และหน่วยที่คนตรวจแล้ว | ไม่จับราคาคนละบรรทัดมาคู่กัน |
| สรุปเงื่อนไขจากหลายหน้า | ข้อความต้นทางและเลขหน้า | ทุกข้อสรุปสำคัญย้อนถึงข้อความได้ |
| กรอกข้อมูลจากภาพหน้าจอ | ค่าที่ควรกรอกและจุดที่ต้องยืนยัน | ไม่เดาข้อมูลที่ภาพอ่านไม่ชัด |
| ร่างข้อความจากเอกสาร | ผู้รับ จุดประสงค์ และข้อห้าม | คนแก้เนื้อหาสำคัญได้ก่อนส่ง |

ตารางนี้เป็นแบบออกแบบการทดลอง ไม่ใช่คะแนนของ Terra ควรเก็บตัวอย่างที่โมเดลเดิมทำได้ดีด้วย เพื่อให้เห็นการถอยหลังที่อาจถูกคะแนนเฉลี่ยกลบ

## จะเทียบต้นทุนและขอบเขตข้อมูลอย่างไร

บันทึกค่า API คำขอที่ต้องทำใหม่ และเวลาที่ผู้ตรวจใช้แก้ในแต่ละงาน แล้วคำนวณต้นทุนต่อชิ้นที่ผ่านตรวจ แยกตัวเลขก่อนส่วนลดออกจากยอดจ่ายจริง เพื่อไม่ให้โปรโมชั่นชั่วคราวตัดสินการเลือกโมเดลระยะยาว

สำหรับ Mimir Suites Cloud ข้อความเอกสารถูกส่งไปยังโมเดลคลาวด์ โดยปิดข้อมูลส่วนบุคคลตามค่าเริ่มต้นก่อนส่ง การทดลองจึงต้องระบุเอกสารที่อนุญาตให้ส่งและผู้ตรวจผลด้วย ใช้กรอบนี้ประกอบการ [เปรียบเทียบทางเลือก Cloud AI](/compare/) ก่อนเลือกจากชื่อรุ่นหรือราคาเพียงอย่างเดียว

วิดีโอด้านล่างเป็นบริบทเครื่องมือสร้าง Agent ของ OpenAI ในปี 2025 ไม่ใช่การสาธิต Terra หรือผลทดสอบชุดเอกสารนี้
