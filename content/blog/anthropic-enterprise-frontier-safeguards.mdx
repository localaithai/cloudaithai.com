## ระบบเฝ้าดูมีข้อมูลอีกชุดหนึ่ง

Anthropic ประกาศ EFS วันที่ 1 กันยายน 2026 โดยให้ข้อมูล monitoring อยู่ใน cloud ที่ลูกค้าควบคุมและทีมลูกค้าตรวจ flag พร้อม rollout เป็นระยะ [แหล่งข่าวทางการ](https://www.anthropic.com/news/enterprise-frontier-safeguards)

การใช้ AI กับเอกสารอาจสร้างข้อมูลหลายชุด ทั้งข้อความที่ส่ง ผลตอบและเหตุการณ์ตรวจสอบ ทีมธุรกิจควรถามเรื่องแต่ละชุด ไม่ถือว่าเงื่อนไขของเอกสารต้นฉบับครอบคลุม log ด้วย ใครเห็นข้อมูลเมื่อเกิด flag และข้อมูลเหล่านั้นถูกเก็บนานเท่าใดมีผลต่อขอบเขตที่เจ้าของงานอนุญาต

## ถามที่เก็บ ระยะเก็บและคนตรวจแยกกัน

ข้อวิเคราะห์คือแยกสิทธิ์บริหาร cloud จากสิทธิ์อ่านเนื้อหาที่ถูกเฝ้าดู ผู้ดูแล infrastructure อาจไม่ควรได้สิทธิ์ดูเอกสารทุกฉบับ ให้ทำรายการบทบาทและขั้นเปิดสิทธิ์เมื่อจำเป็น พร้อมเหตุผลที่ตรวจตามได้

| ชุดข้อมูล | คำถามที่ต้องมีคำตอบ |
| --- | --- |
| คำขอและผล | มีข้อความอะไรอยู่ใน monitoring |
| ที่เก็บ | บัญชี region และผู้ควบคุมที่ตั้งค่าได้ |
| Retention | กำหนดระยะ ลบและจัดการสำรองอย่างไร |
| Review | ใครเห็น flag เนื้อหาและอนุมัติการเปิดดู |

ตารางนี้เป็นเกณฑ์ตรวจที่เสนอ ไม่ใช่ configuration EFS ที่เรายืนยัน หากบางระบบต้องเก็บเหตุการณ์ ให้ระบุข้อมูลเท่าที่จำเป็นและเจ้าของนโยบาย ไม่เปิดบันทึกทุกอย่างเพียงเพื่อให้ตรวจง่าย

## ทดลองเหตุการณ์กับข้อมูลจำลอง

สร้างเหตุการณ์ทดลองด้วยเอกสารจำลองที่ไม่มีข้อมูลลับ ตรวจว่าคนแต่ละบทบาทเห็นข้อมูลตามที่กำหนดหรือไม่ ลองการถอนสิทธิ์และการลบเมื่อครบระยะ รวมสำเนาที่ใช้ตรวจหรือสำรอง เพื่อไม่ให้การลบหน้าหลักถูกเข้าใจว่าลบทุกชุดแล้ว

กำหนดขั้นเมื่อมี flag ที่ต้องตรวจ เช่น ผู้รับเรื่อง วิธีขอเปิดข้อมูลและวิธีบันทึกการตัดสินใจ ไม่ให้ระบบแจ้งเตือนเป็นคำตัดสินผิดถูกโดยอัตโนมัติ การควบคุม cloud ฝั่งลูกค้าไม่ได้รับรองว่านโยบายครบหรือว่ามีบริการพร้อมใช้ตามทุกเงื่อนไขที่ต้องการ
